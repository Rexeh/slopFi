# Renewals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Renewals register that reminds the household at month close before contracts roll over, and records quotes and prices at each renewal.

**Architecture:** One domain module (`renewals.py`) owns the register, due window, mortgage sync, events and suggestions over four new SQLite tables. `review.py` gains a sixth checklist step backed by a deferral table. A new route module and templates render the page in slopFi's existing components. The approved mockups live in `.impeccable/mocks/renewals/` so `/impeccable` can verify the build against them.

**Tech Stack:** Python 3.12, FastAPI, Jinja2, htmx, SQLite, pytest, pytest-playwright.

**Spec:** `docs/superpowers/specs/2026-11-18-renewals-design.md`

## Global Constraints

- Lead times: mortgage fix **183 days**, every other kind **91 days**. Editable per renewal (`lead_days`; null means the default).
- Due when `ends_on − lead ≤ today + 35`. Next six months = `ends_on ≤ today + 183` and not due. Everything else is Later.
- Annualise: `month × 12`, `year × 1`, `once × 1`.
- Kinds: `insurance`, `energy`, `broadband`, `mobile`, `car`, `mortgage`, `other`. Periods: `month`, `year`, `once`. Outcomes: `stayed`, `switched`, `haggled`, `done`.
- The renewals step is judged only for `review.latest_open_month(conn, today)`. Any other month reports it as done.
- A renewal never blocks closing a month: "Look at it next close" defers it for that checklist month only.
- The mortgage is never entered twice. Its end date, price, period and provider are read from the holding. A renewal may write only the holding's `fix_end`, `rate`, `monthly_payment` and `provider`.
- No network calls, and no new dependencies.
- Copy follows the app's voice: sentence case, a toast after every save, and deletes ask first and say what goes with the item.
- Schema version goes from 9 to 10. New tables only, so the migration list entry is `10: []`.
- Commits are left to the user. Each task ends with a passing test run instead.

## Review Focus

1. **Blank optional numbers from forms** ("" for quote, other quote, price). These must store NULL, never 0. A blank quote means no saving is shown. Test in Task 3.
2. **Mixed periods** (a yearly quote against a monthly new price). The saving compares annualised figures. Test in Task 3.
3. **A mortgage whose holding loses its `fix_end` or is deleted.** The row is archived with its history, not crashed on and not deleted. Test in Task 2.
4. **A renewal whose end date has passed.** It stays in Due, with `days_left` negative. Test in Task 2.
5. **Deleting the latest event when it is the only one, or when there is none.** One event restores the old term. None returns False and changes nothing. Test in Task 3.

### Task 2: Schema and register

**Files:**
- Modify: `src/slopfi/db.py`: append four tables to `SCHEMA`, add `MIGRATIONS[10] = []` and set `SCHEMA_VERSION = 10`.

Tables (columns exactly as in the spec's Data section):

- `renewals`: includes `archived_at TEXT` and `holding_id INTEGER UNIQUE REFERENCES holdings(id) ON DELETE SET NULL`.
- `renewal_events`: `renewal_id` references `renewals(id) ON DELETE CASCADE`.
- `deferred_renewals`: `month TEXT, renewal_id INTEGER REFERENCES renewals(id) ON DELETE CASCADE, deferred_at TEXT`, primary key (`month`, `renewal_id`).
- `dismissed_renewal_suggestions`: `payee_key TEXT PRIMARY KEY, dismissed_at TEXT`.

**Interfaces:**
- Produces in `renewals.py`:
  - Constants: `KINDS: tuple[str, ...]`, `KIND_LABELS: dict[str, str]`, `PERIODS`, `OUTCOMES`, `DEFAULT_LEAD = {"mortgage": 183}`, `LEAD_DAYS = 91`, `LOOKAHEAD_DAYS = 35`, `SOON_DAYS = 183`.
  - `annual(price: float | None, period: str | None) -> float | None`
  - `sync_mortgages(conn) -> None`
  - `register(conn, today: date) -> list[dict]`. Runs `sync_mortgages` first. Sorted by group (due, soon, later, archived), then by `ends_on`.

    Each dict has: `id, name, kind, kind_label, provider, owner, ends_on, lead_days, reminder_on, days_left, group, price, price_period, payee_key, latest_payment, how_paid, notes, holding_id, archived, last`.

    - `group` is one of `"due" | "soon" | "later" | "archived"`.
    - `last` is `None` or `{"outcome", "saved": float | None, "rise_pct": float | None}`.
    - `how_paid` is "direct debit", "standing order" or "card" from the linked payee's type code. Otherwise it is "paid monthly", "paid yearly" or "one payment".
    - `latest_payment` is the latest linked payment, set only when it differs from a monthly `price` by more than 1%.
  - `due(conn, today: date) -> list[dict]`: the `group == "due"` rows.
  - `get(conn, renewal_id: int, today: date) -> dict | None`
  - `save_renewal(conn, data: dict, renewal_id: int | None = None) -> int`. Keys: `name, kind, provider, owner, ends_on, lead_days, price, price_period, payee_key, notes`. It trusts its input; the route validates.
  - `delete_renewal(conn, renewal_id: int) -> bool`. Returns False, and deletes nothing, for a row with `holding_id`.

### Task 3: Recording renewals and history

**Files:**
- Modify: `src/slopfi/renewals.py`
- Test: `tests/test_renewals.py`

**Interfaces:**
- Consumes: Task 2 functions.
- Produces:
  - `record(conn, renewal_id: int, data: dict, today: date) -> int`. Keys: `outcome, quote, quote_period, other_quote, other_period, other_provider, new_provider, new_price, new_period, new_ends_on, new_rate, new_payment`.
    - Stores the event with `old_*` taken from the current term.
    - Updates the renewal's `provider, price, price_period, ends_on`. For a mortgage it updates the holding's `fix_end, rate, monthly_payment, provider` instead.

  - `delete_latest_event(conn, renewal_id: int) -> bool`: restores `old_*` to the renewal (or to the holding's four fields for a mortgage), then deletes the event.
  - `saved_in_year(conn, year: int) -> float`: the sum of non-null `saving` over events with `recorded_on` in that year.

| Method | Path | Does |
|---|---|---|
| GET | `/renewals` | The page. Query: `renew=<id>` (that row expanded), `edit=<id>` (form filled), `add=1&payee=<key>` (form prefilled from the suggestion). |
| POST | `/renewals` | Create. |
| POST | `/renewals/{id}` | Update. |

| GET | `/renewals/{id}/renew` | `_renewal_row.html` expanded, for `hx-get`. |

| POST | `/renewals/suggestions/dismiss` | Form `payee_key`. |

Validation:

- `name` required.
- `ends_on` required unless the row is a mortgage, and must be an ISO date.
- Prices are ≥ 0 or blank (blank becomes None).
- `lead_days` is a whole number from 1 to 730, or blank.
- `new_ends_on` must be later than today.

Page content, copy and grouping follow the spec's Page and Recording sections and `.impeccable/mocks/renewals/renewals-approved.html`:

- Summary: yearly cost, "saved at renewal in <year>", suggestions waiting.
- Groups: "Due before the next close", "Next six months", "Later", and a collapsed `<details>` "Archived".
- Owner choices from `household.owner_choices`.
- The delete confirmation uses the app's existing confirm pattern: "Delete Car insurance? Its renewal history goes with it." Undoing a mortgage renewal says it also restores the fix end, rate, payment and lender on Net worth.

`renewals.js` reads the quote, its period, the new price and its period, and writes a result line using the same annualising as `renewals.annual`.
